## 3. Git в IDE и сравнение с SVN

Файл ide_notes.md содержит три удобства VS Code: diff, частичный staging,
навигация по истории; сложные операции удобнее выполнять в терминале.
Файл svn_comparison.md содержит письменные ответы. Git хранит историю
локально, позволяет делать коммиты без сети и использует лёгкие ссылки-ветки.
SVN отправляет коммиты в центральный сервер; он сохраняет применение
в существующих корпоративных процессах. SVN-ветки реализуются копиями
каталогов, но их создание на сервере использует cheap copies.

Снимок действий в Source Control не получен: факт наличия файла заметок
не заменяет демонстрацию интерфейса IDE.

## 5. Ответы к защите

- GitHub Flow: ветка → изменение → коммит → push → PR → review → merge.
- PR — запрос на рассмотрение изменения; merge — операция объединения.
- Review помогает найти ошибки и проверить понятность решения.
- `feat:` обозначает новую функциональность в Conventional Commits.
- Первый push: `git push -u origin feature/hobby-project`.
- CLI нужен для серверов, автоматизации и точного управления историей.
- Merge сохраняет историю; rebase переносит неопубликованные коммиты
  и меняет их идентификаторы. Общую историю без согласования не переписывают.
