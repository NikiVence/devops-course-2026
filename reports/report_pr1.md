## 4. SSH и фактический статус

Ранее создан отдельный ключ Ed25519 для учебной работы. Проверка 30.09.2026
не подтвердила вход: сервер вернул Permission denied (publickey).
Публикация через HTTPS работает. Для буквального выполнения SSH-части
необходимо добавить публичный ключ в аккаунт GitHub и повторить `ssh -T`.
Приватный ключ не включается в репозиторий и отчёт.

![Проверка SSH](pr1/ssh_check.txt)

## 5. Контрольные вопросы

- DevOps уменьшает разрыв между разработкой и эксплуатацией через общую
  ответственность, автоматизацию и обратную связь.
- CALMS: культура, автоматизация, бережливые процессы, измерения, обмен знаниями.
- Публичный SSH-ключ хранится на сервере, приватный — у владельца;
  пароль аккаунта не требуется передавать при каждой Git-операции.
- В методичке приведены метрики DORA: частота развёртываний, время доставки
  изменения, доля неудачных изменений и время восстановления.
